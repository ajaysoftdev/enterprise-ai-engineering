# Engineering Walkthrough

## 1. Select a project
Choose a bounded task from the project catalogue. Read scope, assumptions and acceptance criteria.

## 2. Establish baseline
Record repository, branch, starting commit, runtime, build command, test result and environment blockers.

## 3. Create a ticket
Use the bug/feature template. Include reproducible context, expected behaviour, non-goals and acceptance criteria.

## 4. Inspect before changing
Trace request/data flow through source, persistence, configuration and tests. Separate confirmed facts from hypotheses.

## 5. Implement incrementally
Make the smallest change that satisfies the ticket. Avoid unrelated refactoring. Add tests for success, invalid input and boundaries.

## 6. Review and verify
Inspect the full diff, run relevant checks, review security implications and align documentation with code.

## 7. Record evidence
Capture task, commits, files changed, commands/results, findings, review notes, limitations and AI assistance.

## 8. Publish accurately
Change status only when implementation and verification evidence exist. Distinguish upstream code, original work and AI-assisted changes.
