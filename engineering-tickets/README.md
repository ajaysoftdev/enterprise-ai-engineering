# Engineering Tickets

This area contains bounded engineering tasks used for implementation, debugging, testing and code-review practice.

## Ticket lifecycle

1. Describe the observed problem or requested behaviour.
2. Identify scope, assumptions and affected components.
3. Define reproducible steps and acceptance criteria.
4. Investigate before changing code; record the root cause when confirmed.
5. Implement the smallest appropriate change.
6. Add or update tests and run relevant checks.
7. Document the result, evidence and remaining limitations.

## Ticket templates

- [Bug report template](templates/bug-report-template.md)
- [Feature request template](templates/feature-request-template.md)

Tickets based on Spring PetClinic should remain within its actual domain and codebase. Any deliberately introduced defect must be isolated to a clearly identified practice branch and must not be presented as an upstream defect.

## Status

Templates are provided for future exercises. No tickets are represented as completed fixes.
